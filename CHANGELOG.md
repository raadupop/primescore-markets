# Changelog

## 2026-09-25

- Engine milestone M3: composite and dislocation. Every new assessment of a context member records a composite and its IV dislocation at that signal's observation time, under its correlation id, with the configuration version it used ([ADR-0004](doc/adr/0004-composite-and-dislocation-resolutions.md); SRS amendments proposed in [v2.3.4](doc/research/srs-revision-v2.3.4-proposal.md)). `GET /api/classification/composite` and `/dislocation` (with `as_of` and `context`), `PUT /api/config/weighting-scheme` and `/dislocation-threshold` are live; each accepted change is a new configuration version with its diff, and a change the formulas cannot use is refused with every problem listed. Seeded settings are labelled "uncalibrated default". Overview shows the composite, dislocation, scenario and a five-year sparkline per context; History charts the daily composite and dislocation with regime shading and a table view; Configuration shows the active version and its history.
- Engine milestone M2: classification. Every recorded signal is sent to the Python classifier with a reference window built from values observed strictly before it; each outcome (an assessment with its trace, a CLS-004 fallback with its staleness, or the reason there is none) is recorded in the ledger under the signal's correlation id. Macro prints are classified only against a sourced consensus row (`apps/engine/data/consensus/`), otherwise they stay awaiting consensus. `GET /api/classification/assessments` is live. Assessment columns and detail on the signal tape, classification coverage and consensus files on Sources and health. Date-time query parameters without an offset are read as UTC on every host, and an unreadable one is a 400.
- Classifier 0.2.0 (additive, ADR-0005): an optional `reference_window` on `POST /classify` lets the caller supply the history; such requests neither read nor change the process's rolling windows and are served before bootstrap completes.
- Engine milestone M1: signal ingestion. `POST /api/admin/signals` validates each signal against the contract and records it or a structured rejection; resubmitting an observation is idempotent. A FRED adapter backfills from 2011 and pulls daily with point-in-time timestamps (index closes at 16:15 New York, CPI and claims at their first release). Signal tape, ledger entry view and adapter status screens. Resubmitting a signal with a different payload is refused; one unstorable number rejects only its own signal; the `fred:` source prefix is reserved for the adapter; a failing or timed-out FRED series marks the run partial without stopping the others, and a run in which every series fails is recorded as failed. Data limits in [apps/engine/LIMITATIONS.md](apps/engine/LIMITATIONS.md).
- Engine API contract 1.1.0 (additive): `GET /health`, an optional `context` query parameter on `GET /classification/composite` and `GET /classification/dislocation` (default `equity`), and documented `501` responses for the Milestone B position, exit, risk, execution-mode and approval endpoints.
- Engine milestone M0: .NET 10 solution under `apps/engine` with build-time contract generation, the hash-chained ledger and its verification command, module skeletons, bearer-token roles, the UI shell with health, structural and black-box acceptance suites, and a .NET stage in the shared gate and CI. No ingestion, classification or decisions yet.
- Restyled the local replay dashboard to the Markets site design: dark theme, Space Grotesk (bundled locally with its OFL licence), lime accent, bar logo. Asset links are versioned so browsers drop the cached old design. Replay behaviour, data and HTTP interface are unchanged.

## 2026-09-22

- Renamed the venture and GitHub repository to PrimeScore AI / `primescore-ai`, preserving history; documented implemented and planned scope.
- Repaired signed and zero-deviation classification, parametric-fit rejection, history sufficiency and bootstrap readiness. Historical source values and expected bands remain unchanged; three macro anchors remain skipped.
- Added Linux/Windows GitHub Actions for both OpenAPI contracts, six dependency boundaries, fitness tools and tests. Validation now rejects missing tools and unsuccessful fitness subprocesses; Stop retries remain bounded.
- Added static brand and Markets pages with interactive historical classification examples.
- Built a local three-view historical VIX/OVX replay dashboard using real HTTP classification. Scenarios are explicitly uncalibrated and withheld for degraded or unavailable classification.
- Recorded the audit, design contradictions, external-review controls and remaining calibration/provider work. The .NET engine, live ingestion and independently validated volatility forecasting remain planned.
