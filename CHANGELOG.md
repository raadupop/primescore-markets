# Changelog

## 2026-10-02

- Slice specs ([doc/slices/](doc/slices/README.md)): eight slices in build order, each with SRS IDs, design links, UI tests and a click-through on a demo copy of the ledger. Slices 1 (volatility state) and 2 (events ahead) were run on real data: VIX 16.34 on 2026-09-30 at the 35.5th percentile and the 9-day/30-day ratio −0.131 both match Cboe's files.
- SRS v2.4.0: CLS-006 descriptive; DEC-005, ANA-003, SIG-006, CLS-010 and CAT-001 to CAT-003 added; ANA-001 and §11 verified on Volmageddon; §9 events kept as a regression record because the state gate fires on or after a shock, never before.
- `scripts/build-demo-ledger.ps1` copies the live ledger and records a state-gate replay; `start-markets.ps1 -Database <path> [-PullSources]` serves a copy and refuses sources on the live ledger.
- Fixes found on the demo copy: a relative `--database` created an empty database (now refused); the replay page rendered every record of a ten-year run (54 MB, now the first 300); Cboe's CDN refused 1 to 3 of 10 files per run with HTTP 403 (now retried, with a User-Agent); dates printed as 1/4/2016 on two pages; "83.1th percentile"; journal tiles that did not add up; escaped "+" in formatted ledger JSON.
- Test harness: two intermittent gate failures fixed. Test classes cleared every SQLite pool in the process while parallel classes were opening connections (now each clears only its own database), and the acceptance harness closed a child process's log before its last output lines arrived.

## 2026-09-29

- Engine API contract 1.3.0 (additive): `GET /api/catalysts` (`from` defaults to now, `to` to 30 days later, optional `family`) and `GET /api/catalysts/{catalyst_id}` with every schedule vintage. Each catalyst carries its canonical id, source provenance, never-rescheduled flag and the 9-day/30-day ratio (VIX9D ÷ VIX − 1) with its weekday-matched baseline percentile and n; no index levels are served. Catalyst calendar page (`/catalysts`, next 30 days; consensus "not yet captured") and the `import-catalysts --file <csv> [--force]` CLI verb for curated back-fill.

## 2026-09-25

- Engine milestone M6 (SEC-001/002, NFR-003): operator cookie sign-in, protected UI actions, CSRF checks, login throttling and configuration editing with version-conflict detection. Interactive password setup writes a hash to user-secrets; the bearer API remains separate. [Runbook](docs/ENGINE.md) covers setup, ingestion, replay, credentials, backup and ledger verification.
- Engine milestone M5 (ANA-001): `POST /api/replay`, temporary configuration overrides, stored replay timelines and the ten SRS validation targets. `evaluate-validation` writes `apps/engine/var/validation-report.md`; the Replay screen shows the same results. Replays reuse recorded classifications and recalculate composites and decisions without changing live settings or decisions ([ADR-0006](doc/adr/0006-replay-from-recorded-classifications.md)).
- Engine milestone M4: decisions and audit. Every dislocation gets a DEPLOY or IDLE decision under the triggering signal's correlation id; DEPLOY needs every configurable condition to hold (brief §9.6), and each condition's required and actual value is recorded with the top contributing and dissenting signals ([ADR-0005](doc/adr/0005-decisions-conditions-explanations-and-time.md)). `GET /api/decisions`, `/decisions/{id}`, `/audit` and `PUT /api/config/deploy-conditions` are live; `/logs` traces one correlation id from ingestion to decision. Decisions screen and explorer (conditions, signals, trace, audit chain segment), the latest decision on Overview, DEPLOY markers on History, and a signal's decisions on the tape. No decision places an order: v1 runs in simulation mode.
- Engine milestone M3: composite and dislocation. Every new assessment of a context member records a composite and its IV dislocation at that signal's observation time, under its correlation id, with the configuration version it used ([ADR-0004](doc/adr/0004-composite-and-dislocation-resolutions.md); SRS amendments proposed in [v2.3.4](doc/research/srs-revision-v2.3.4-proposal.md)). `GET /api/classification/composite` and `/dislocation` (with `as_of` and `context`), `PUT /api/config/weighting-scheme` and `/dislocation-threshold` are live; each accepted change is a new configuration version with its diff, and a change the formulas cannot use is refused with every problem listed. Seeded settings are labelled "uncalibrated default". Overview shows the composite, dislocation, scenario and a five-year sparkline per context; History charts the daily composite and dislocation with regime shading and a table view; Configuration shows the active version and its history.
- Engine milestone M2: classification. Every recorded signal is sent to the Python classifier with a reference window built from values observed strictly before it; each outcome (an assessment with its trace, a CLS-004 fallback with its staleness, or the reason there is none) is recorded in the ledger under the signal's correlation id. Macro prints are classified only against a sourced consensus row (`apps/engine/data/consensus/`), otherwise they stay awaiting consensus. `GET /api/classification/assessments` is live. Assessment columns and detail on the signal tape, classification coverage and consensus files on Sources and health. Date-time query parameters without an offset are read as UTC on every host, and an unreadable one is a 400.
- Classifier 0.2.0 (additive, [classifier ADR-0005](apps/classification/doc/adr/0005-caller-supplied-reference-window.md)): an optional `reference_window` on `POST /classify` lets the caller supply the history; such requests neither read nor change the process's rolling windows and are served before bootstrap completes.
- Engine milestone M1: signal ingestion. `POST /api/admin/signals` validates each signal against the contract and records it or a structured rejection; resubmitting an observation is idempotent. A FRED adapter backfills from 2011 and pulls daily with point-in-time timestamps (index closes at 16:15 New York, CPI and claims at their first release). Signal tape, ledger entry view and adapter status screens. Resubmitting a signal with a different payload is refused; one unstorable number rejects only its own signal; the `fred:` source prefix is reserved for the adapter; a failing or timed-out FRED series marks the run partial without stopping the others, and a run in which every series fails is recorded as failed. Data limits in [apps/engine/LIMITATIONS.md](apps/engine/LIMITATIONS.md).
- Engine API contract 1.1.0 (additive): `GET /health`, an optional `context` query parameter on `GET /classification/composite` and `GET /classification/dislocation` (default `equity`), and documented `501` responses for the Milestone B position, exit, risk, execution-mode and approval endpoints.
- Engine milestone M0: .NET 10 solution under `apps/engine` with build-time contract generation, the hash-chained ledger and its verification command, module skeletons, bearer-token roles, the UI shell with health, structural and black-box acceptance suites, and a .NET stage in the shared gate and CI. No ingestion, classification or decisions yet.
- Restyled the local replay dashboard to the Markets site design: dark theme, Space Grotesk (bundled locally with its OFL licence), lime accent, bar logo. Asset links are versioned so browsers drop the cached old design. Replay behaviour, data and HTTP interface are unchanged.
